# Score to MusicXML

Turns a photo, scan or PDF of sheet music into a MusicXML 2.0 file you can open in Sibelius 7. It can run on the CPU, an NVIDIA graphics card or an AMD graphics card.

## The window

Double-click **`Score to MusicXML.bat`**. You can also drop images or PDFs onto it.

1. **Pages:** drop images or PDFs into the list, or click *Add files…*. Pages are joined top to bottom into one score; use *Move up* / *Move down* to fix the order.
2. **Title / Composer:** optional. Leave Title blank to use the title found on the page.
3. **Save as:** defaults to the first page's name with `.xml`, in the same folder. Existing files aren't overwritten; you get `name (2).xml` instead.
4. **Processor:** *Automatic* picks the fastest one installed for your graphics card. A processor that isn't set up yet shows an **Install** button (see below).
5. **Convert.** When it finishes, **Open in Sibelius** opens the file directly. The first time, it asks where `Sibelius.exe` is if it can't find it. **Show in folder** opens the output folder.

The window lists any bars whose rhythms don't add up to the time signature. That usually means a misread note, so check those bars first. *Show details* shows the full log.

## Processors

| Processor | How it runs | Time for the sample page* | Disk space |
|---|---|---|---|
| CPU | always available | ~18 s | ~0.5 GB |
| NVIDIA GPU (CUDA) | NVIDIA cards, recent driver | ~12 s | ~2.3 GB |
| AMD GPU (DirectML) | AMD cards on Windows, through DirectML | ~15 s | ~0.6 GB |

\* One dense page of piano music, measured on an RTX 3080. A few seconds of each run is start-up time, so the GPU's lead grows with more pages.

- Each processor gets its own folder (`.venv`, `.venv-nvidia`, `.venv-amd`), because the CPU, CUDA and DirectML builds of the inference library can't be installed side by side. The Install button creates the folder, downloads everything, then loads a model on the card to confirm it works. Delete a folder to uninstall that processor.
- **AMD on Windows:** homr only supports AMD through ROCm, which is Linux-only. On Windows, `homr_runner.py` routes homr's two heavy models through DirectML instead. It uses the full-precision models, because the half-precision ones produce errors under DirectML. The step-by-step decoder stays on the CPU, because DirectML's per-call overhead made it 4× slower there.
- DirectML runs on any DirectX 12 card, so the AMD option also works on Intel or NVIDIA cards. On an NVIDIA card, CUDA is faster.
- With more than one graphics card, set the environment variable `S2X_DML_DEVICE` (0, 1, …) to choose which one DirectML uses.

All three give identical notes on the test page.

## Command line

```bat
score2xml.bat my-score.jpg
score2xml.bat page1.jpg page2.jpg --title "Minuet in G" --composer "Petzold" --device nvidia
score2xml.bat scan.pdf -o "D:\Scores\minuet.xml"
python score2xml.py --install amd
```

`--device` is `auto` (default), `cpu`, `nvidia` or `amd`. Use `-v` to see the full log. Dropping files onto `score2xml.bat` works too.

## What it does

1. Turns photos upright using their rotation data. PDFs are rendered at 300 dpi.
2. Runs [homr](https://github.com/liebharc/homr), an open-source optical music recognition engine, which writes MusicXML 4.0.
3. Rewrites the result as **MusicXML 2.0**, the version Sibelius 7 reads, saved uncompressed as `.xml`. homr also puts some elements in an order the standard doesn't allow, and Sibelius rejects such files as invalid, so the script fixes the order too.
   - It removes the 99 elements and 200 attributes that MusicXML 3.0–4.0 added. That list, in `musicxml20.py`, was generated by diffing the official 2.0 and 4.0 DTDs.
   - It applies the value rules from the official 3.0→2.0 stylesheet (`to20.xsl`).
   - Output is checked against the official MusicXML 2.0 DTD and XSD.
   - It also drops homr's placeholder page size, and drops the title when homr has mistaken a tempo mark for one.
   - The notes themselves aren't changed. The only 3.0+ feature homr currently writes is the instrument-sound tag ("keyboard.piano"). The full list is there in case a later homr version adds more.

## Getting good results

- Expect to fix some notes, accidentals and rhythms by hand, especially from phone photos.
- Shoot flat-on in good light with the whole page in frame. A 300 dpi scan beats a photo.
- Printed music works; handwritten music mostly doesn't.
- Lyrics, chord symbols, most articulations and text aren't recognised. Notes, rests, clefs, keys, time signatures, ties, slurs, dynamics and arpeggios are.

## Files

| File | What it is |
|---|---|
| `Score to MusicXML.bat` | opens the window |
| `score2xml_gui.py` | the window (tkinter) |
| `score2xml.py` | conversion, clean-up for Sibelius, processor installs, command line |
| `musicxml20.py` | what MusicXML 2.0 lacks compared with 4.0 (generated from the official DTDs) |
| `homr_runner.py` | runs homr inside a processor's environment and switches it to the GPU |
| `score2xml.bat` | command-line / drag-and-drop launcher |

Settings (last processor, where Sibelius is) are kept in `%APPDATA%\score2xml\settings.json`.

## Setting up on another PC

You need Python 3.11 or 3.12. Copy the `.py` and `.bat` files, then in that folder run:

```bat
python score2xml.py --install cpu
```

Then open the window and install the GPU processors from there.
